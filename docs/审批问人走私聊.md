# 审批「问人」走私聊（DM）

> 归属：dsh-matrix-agent（`@evlon/dsh-bridge` 运行时行为）
> 背景：解决「无头（服务器无人值守）环境下，数字分身的审批请示到不了主人手机」的问题。

## 一、问题

DSH 有两类「问人」通道，落点不同，风险不同：

| 通道 | 机制 | 无头环境风险 |
|---|---|---|
| `ask_user_question` / `plan-mode`（`agentPreset: standard`） | 推给 web answerer（浏览器） | 🔴 主人不在电脑旁 → 请示到不了人 |
| `approval/request`（红线工具审批） | bridge 拦截 → 转发 | ⚠️ 原实现发**群聊房间**，请示内容暴露给房间所有成员 |
| `matrix_request_owner_decision`（秘书请示） | 走 `waitOwnerDecision`，DM 私聊主人 | ✅ 本来就对 |

本改动针对前两类：

1. **堵住 `standard` preset 的「问人」工具**：无头分身不应挂载 `ask_user_question` / `plan-mode`，
   应使用岗位 preset（`pm`/`dev`/`qa`…），岗位 preset 的问人走 `matrix_request_owner_decision`
   （DM 私聊主人，有超时兜底，不会卡死）。
2. **审批「问人」从群聊改为 DM 私聊主人**：请示内容与主人的批准/拒绝不再暴露在群里。

## 二、改动内容

### 1. `askRoom`：审批问人走私聊

- 设了 `owner` 且通道有 `sendDm` 能力时，审批请示发 **DM 私聊 owner**，不再发群聊房间；
- 记录 `ownerDmToWorkRoom` 映射（DM 房 → 工作房间），使主人在 DM 房回复「批准/拒绝」时能反查到审批队列；
- 无 `owner` 或无 `sendDm` 能力时，退回原群聊行为（兼容旧部署）；
- 审批批准后写记忆授权时，用反查到的**工作房间**（而非 DM 房）作为授权 scope。

### 2. `handleOwnerlessApproval`：无主审批兜底

秘书/前台接待/subagent 会话**不绑定工作房间**（`roomForSession` 返回 undefined），
它们的 `approval/request` 原实现会 `next()` 漏给 web answerer → 静默 fail-closed，
请示到不了主人手机。

现在新增兜底：

- `ownsAgentSession()` 按会话 id 前缀 `matrix-<localpart(userId)>-` 找到创建该 agent 的账号；
- 命中后走 `handleOwnerlessApproval`，用合成 key `__ownerless_approval__` 承载审批队列，
  「问人」仍发 DM 私聊主人；
- `grantOnApprove` 恒为 `false`：无主审批没有真实房间可记授权 scope，
  且秘书/前台自主发起的审批本就该**每次都问主人**（安全优先）；
- 超时 `settle('unavailable')`，与 `askRoom` 一致，**不会卡死**；
- 仍无法归属（不属于任何已知账号的 agent）→ 才 `next()` 交给 web answerer，
  官方框架会 fail-closed（无 answerer 时 resolve `unavailable`）。

### 3. `agentPreset` 默认值警示

`config.ts` 的 `agentPreset` 与 `cordis.patch.example.yml` 都加了注释警示：

> 无头环境别用 `standard`——它会挂载 `ask_user_question` / `plan-mode` 两个「问人」工具，
> 问题会推给 web answerer 而主人不在电脑旁。数字分身应配岗位 preset。

⚠️ 注意：`agentPreset` 的**默认值仍是 `standard`**（未改）——因为生产 `cordis.patch.yml`
已显式配岗位 preset，`standard` 只是「未配岗位」的兜底；硬改成某个岗位 preset 反而会导致
「该岗位不存在时 agent 裸奔」。故只做警示注释，不硬改默认值。

## 三、语义变化（部署后需知晓）

- ✅ 审批请示（红线工具 `bash`/`write`、主动发消息等）从「群里问」变为「私聊主人问」；
- ✅ 群里同事看不到请示内容与主人的批准/拒绝；
- ⚠️ 主人的审批应答也从「群里回」变为「私聊回」——审批流不再留痕于群。
  若需要「审批结果摘要回群（但不暴露内容）」，需另行加逻辑，当前未做。
